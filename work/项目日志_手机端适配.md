# 项目日志：手机端适配改造

## 为什么要做这件事？

这个「个人 AI 工作台」起初是为电脑屏幕设计的。在手机上打开时，页面会变得很奇怪——侧边栏占满半个屏幕，按钮叠在一起，文字挤到看不见。

**就像一本杂志被印在了一张小纸条上，所有排版都乱了。**

所以我们需要让这个应用能「自适应」——在不同尺寸的屏幕上都能正常阅读和操作。这就是**响应式设计（Responsive Design）**。

---

## 核心思路：三套方案，一套代码

响应式设计就像**变形金刚**——同一个页面，在不同屏幕上变成不同的样子，但内核是同一套代码。

我们用 **CSS 媒体查询（Media Query）** 来实现。它就像给页面装了一个「身高测量仪」：

```css
@media (max-width: 768px) {
  /* 当屏幕宽度小于 768px（手机）时，执行这里的样式 */
}
```

### 三种屏幕状态

| 屏幕宽度 | 代表设备 | 布局策略 |
|---------|---------|---------|
| > 1100px | 大屏电脑 | 三栏布局：侧边栏 + 内容 + 概况 |
| 768-1100px | 小屏电脑/平板 | 两栏布局：侧边栏 + 内容（概况隐藏） |
| < 768px | 手机 | 单栏布局：抽屉菜单 + 底部导航 |

---

## 手机端做了哪些改造？

### 1. 侧边栏 → 抽屉式菜单

**电脑上**：侧边栏固定在左侧，像一本书的脊背，始终可见。

**手机上**：侧边栏变成了「抽屉」——平时藏在屏幕左边，点汉堡按钮（☰）才滑出来，点遮罩层（半透明背景）就收回去。

> **类比：** 就像你家的衣柜门。打开时才看到里面的东西，关上就不占客厅空间。

**技术实现：**

```css
.wb-sidebar {
  position: fixed;          /* 固定定位，不随页面滚动 */
  left: 0; top: 0; bottom: 0;
  transform: translateX(-100%);  /* 向左平移 100%，隐藏在屏幕外 */
  transition: transform .32s;    /* 动画过渡，像推拉门缓缓滑出 */
}
.wb-sidebar.mobile-open {
  transform: translateX(0);      /* 平移回原位，显示在屏幕上 */
}
```

`transform` 和 `transition` 组合，实现了一个平滑的滑入动画。`translateX(-100%)` 意思是「向左移动自身宽度的一整倍」，`-100%` 就是完全移出屏幕。

### 2. 底部导航栏

手机上新增了一个**固定在屏幕底部的导航栏**，显示所有页面的图标。

> **类比：** 就像 iPhone 底部的 Dock 栏，或者微信底部的「微信/通讯录/发现/我」。手指够得到，不用去够屏幕顶部的按钮。

技术要点：
- `position: fixed; bottom: 0` 固定在底部
- `flex: 1` 让所有按钮平分宽度
- 当前页面用 `var(--accent)` 红色高亮，顶部有一条红色线作为指示

### 3. 汉堡菜单按钮

一个固定在屏幕左上角的 ☰ 按钮，点击后抽屉式侧边栏滑出。再点一次（或点遮罩层）侧边栏收回。

按钮的文字在 ☰ 和 × 之间切换，这是一个简单的视觉反馈——告诉用户「这个按钮可以打开/关闭菜单」。

### 4. 所有页面布局改为单栏

电脑上的多栏布局在手机上全部变成一栏：

- **主页瀑布流**：原本两栏并排的卡片 → 上下排列
- **倒计时 + 日历**：原本左右并排 → 上下排列
- **写作编辑器**：原本左右分栏（编辑区 + 预览区）→ 上下排列，预览区在编辑区下方
- **任务看板**：原本三栏并列（待办/进行中/已完成）→ 上下排列

> **类比：** 就像把一张横向的报纸折成纵向——内容没变，但排版方式变了。

### 5. 间距缩小

手机屏幕寸土寸金，我们把所有内边距（padding）从 36px 缩小到 16px，让内容区域的利用率更高。

### 6. 登录页适配

登录框在手机上不再居中显示大片空白，而是紧凑地填满屏幕宽度，输入框占满整行，方便手指点击。

## 关键技术：CSS 媒体查询

### 基本语法

```css
@media (条件) {
  /* 条件满足时执行的样式 */
}
```

条件可以是：
- `max-width: 768px` — 屏幕宽度**小于等于** 768px
- `min-width: 769px` — 屏幕宽度**大于等于** 769px

### 优先级

CSS 媒体查询中的样式会覆盖同名的普通样式。这就像「特殊情况特殊处理」——默认是电脑布局，但检测到手机屏幕时就覆盖成手机布局。

### 为什么选择 768px 作为手机断点？

这是业界惯例：iPhone 的屏幕宽度大约 375-414px，iPad 竖屏是 768px。所以：
- `< 768px` → 肯定是手机
- `768-1100px` → 平板或小屏笔记本
- `> 1100px` → 大屏电脑

## 关键技术：React 的响应式状态管理

除了 CSS，我们还在 JavaScript 中做了响应式处理。

### 1. 检测屏幕宽度

```jsx
const [isMobile, setIsMobile] = useState(() => window.innerWidth < 768)

useEffect(() => {
  const check = () => setIsMobile(window.innerWidth < 768)
  window.addEventListener('resize', check)  // 监听窗口大小变化
  return () => window.removeEventListener('resize', check)  // 清理监听器
}, [])
```

**这段代码在做什么？**
1. 组件加载时，读取当前屏幕宽度，判断是否是手机
2. 监听窗口的 `resize` 事件，每次窗口大小变化时重新判断
3. 组件卸载时移除监听器，避免内存泄漏

> **类比：** 就像给窗户装了一个传感器——窗户大小变了，传感器就通知你，你根据新尺寸决定怎么摆放家具。

### 2. 根据状态渲染不同 UI

```jsx
{isMobile && (
  <button className="wb-hamburger" onClick={() => setMobileMenuOpen(v => !v)}>
    {mobileMenuOpen ? '×' : '☰'}
  </button>
)}
```

`isMobile && (...)` 是 React 的条件渲染技巧——只有 `isMobile` 为 `true` 时，才渲染汉堡菜单按钮。电脑上这个按钮根本不存在。

## 学到什么？

这次改造的核心知识点：

1. **CSS 媒体查询** — 让同一个页面在不同设备上呈现不同布局
2. **`transform: translateX()` + `transition`** — 实现平滑的抽屉滑入动画
3. **`position: fixed`** — 固定定位，用于底部导航栏和汉堡按钮
4. **React 的 `useEffect` + `addEventListener`** — 监听窗口大小变化
5. **React 条件渲染** — `isMobile && <Component />` 语法
6. **`clamp()` 函数** — `font-size: clamp(24px, 6vw, 34px)` 让字体大小随屏幕变化，但有上下限

> **一句话总结：** 响应式设计就是用同一套代码，通过 CSS 和 JavaScript 的组合，让页面在不同尺寸的屏幕上都能正常使用。CSS 负责「外形」的自动调整，JavaScript 负责「交互方式」的切换。
